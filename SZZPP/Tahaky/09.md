# Otázka 9: SQL – CREATE, INSERT, SELECT, normalizace

## CREATE TABLE (PK, FK, NOT NULL, UNIQUE)

```sql
CREATE TABLE student (
    id SERIAL PRIMARY KEY,
    jmeno VARCHAR(100) NOT NULL,
    datum_narozeni DATE NOT NULL,
    studijni_program VARCHAR(100) NOT NULL,
    email VARCHAR(150) UNIQUE
);

CREATE TABLE predmet (
    id SERIAL PRIMARY KEY,
    nazev VARCHAR(100) NOT NULL,
    rocnik INT NOT NULL,
    semestr VARCHAR(10) NOT NULL
);

CREATE TABLE student_predmet (
    student_id INT NOT NULL REFERENCES student(id),
    predmet_id INT NOT NULL REFERENCES predmet(id),
    PRIMARY KEY (student_id, predmet_id)
);
```

## SELECT – vzorové typy dotazů

```sql
-- JOIN: studenti a jejich předměty
SELECT s.jmeno, p.nazev
FROM student s
JOIN student_predmet sp ON sp.student_id = s.id
JOIN predmet p ON p.id = sp.predmet_id;

-- GROUP BY + ORDER BY: počty studentů dle programu
SELECT studijni_program, COUNT(*) AS pocet
FROM student
GROUP BY studijni_program
ORDER BY studijni_program ASC;

-- seskupení s agregací řetězců
SELECT rocnik, STRING_AGG(nazev, ', ') AS predmety
FROM predmet
GROUP BY rocnik;
```

## Normalizační formy (stručně)

- **1NF** – atomické hodnoty v každém sloupci (žádné seznamy/více hodnot v buňce), žádné opakující se skupiny, existuje primární klíč (unikátní řádky).
- **2NF** – splňuje 1NF **a navíc**: žádný neklíčový atribut nezávisí jen na **části** složeného primárního klíče (odstranění částečné závislosti).
- **3NF** – splňuje 2NF **a navíc**: žádný neklíčový atribut nezávisí na jiném neklíčovém atributu (odstranění tranzitivní závislosti) – každý neklíčový atribut závisí "jen na klíči, celém klíči a ničem jiném než klíči".

## Postup normalizace v kostce
Najdi opakující se skupiny/víceznačné atributy → rozděl do samostatných tabulek → over vazby (1:1, 1:N, M:N – u M:N vznikne vazební tabulka jako `student_predmet` výše) → zkontroluj závislosti dle 2NF/3NF.
